# darrshangovender.github.io

Personal portfolio of [Darrshan Govender](https://github.com/darrshangovender), AI engineer in Durban (UTC+2), for [Agulhas Code](https://agulhascode.co.za). Industrial AI, built to be evaluated, audited and trusted.

A static site: plain HTML, one CSS file and a few vanilla JS files. No build step, no framework, no npm, no trackers, no cookies, no third-party requests and no web fonts (system stacks only). It works the same from `file://` and from GitHub Pages.

## What is on the page

| Section | What it is |
|---|---|
| Hero and results strip | Name, the line, focus areas, contact. Every number is copied from a repository README. |
| Industrial AI | The three flagships (asset-health, plant-copilot, maintenance-agent), each with its key result and what that result cannot show. |
| Replays | Two interactive demos driven by real exports from the repositories (see Data provenance). **All demo data is synthetic and labelled so.** |
| LLM infrastructure | cascade, guardrail (with its external-benchmark result), context-compress, sql-guardrails, mcp-gateway, agent-runtime, thinking-loop, rag-eval-harness. |
| How I work, Contact | The four working habits, and how to reach me. |

The two demos:

1. **asset-health replay.** The fused detection score of a synthetic slurry pump rises through its alert threshold, an alert opens, remaining-useful-life intervals appear as daily checkpoints on a calendar lane, and at the snapshot the drafted work order appears. The simulator's hidden answer key is then revealed, so the injected failure can be compared with the interval. A second pump in the same run shows a miss, and the page says so.
2. **maintenance-agent walk-through.** The agent's state machine (plan, gather, draft, verify, await approval, release) stepped through from a real hash-chained audit log. **Approve** opens the gate and shows the signed approval and the released work order. A seeded unsafe draft (the last isolation step removed by a signed edit) is blocked by the verifier with its real reason (`V06 ISOLATION_SEQUENCE: missing mandatory isolation step(s): PRC-LOTO-001@C#5.7`), and the gate refuses, including a replayed earlier approval. The Approve button reveals the recorded, signed approval; the browser signs nothing.

## Run it locally

Nothing to install.

```bash
# either open index.html directly (file:// works) ...
# ... or serve the folder:
python -m http.server 8000      # Windows: py -m http.server 8000
# then open http://localhost:8000/
```

`404.html` uses root-relative paths because GitHub Pages serves it at any missing URL, so test it over HTTP rather than `file://`.

## Layout

```
index.html            the page (inline SVG trace, JSON-LD, Open Graph and Twitter meta, CSP meta)
404.html              not-found page (noindex)
assets/css/site.css   design tokens, light and dark (follows the OS), all components
assets/js/boot.js     adds the "js" class before paint (an external file because the CSP forbids inline script)
assets/js/common.js   helpers (window.PF), mobile nav, scroll reveal
assets/js/replay.js   asset-health replay
assets/js/agent.js    maintenance-agent walk-through
data/*.json, data/*.js   the exported excerpts (the .js copy is the same payload for file://)
assets/img/           favicon.svg, PNG icons, og.png (1200x630)
tools/                exporters, image renderer, QA script (not needed to serve the site)
robots.txt, sitemap.xml, .nojekyll
```

### Why classic scripts and not ES modules

Chrome blocks `<script type="module">` and `fetch()` of local files on `file://`. The demos are written as small IIFE modules that share a tiny `window.PF` namespace, and the data is shipped both as `.json` (for reading) and as a `.js` file that assigns `window.PORTFOLIO_DATA` (for loading). The page's `Content-Security-Policy` meta tag (`default-src 'none'; script-src 'self'; style-src 'self'; ...`) is enforced in both cases, so nothing in the code sets a `style` attribute: dynamic geometry goes through SVG attributes and the CSSOM.

### Motion and accessibility

Scroll reveal, the hero trace drawing in, the chart replay and the approval gate are all disabled under `prefers-reduced-motion: reduce`. In that mode the replay opens on its final state, the walk-through opens at the approval gate, and every control is still available. Interactive controls are real buttons and a range input with a visible focus ring and 44 px touch targets, and the layout is responsive down to 360 px.

## Data provenance

Everything in `data/` was generated by running the repositories' own code, offline, with no API keys:

| File | Produced by | From |
|---|---|---|
| `data/asset-health.{json,js}` | `tools/export_asset_health.py` | asset-health: `simulate --seed 42` (16 assets, 270 days), analysed as of 2025-07-28 with `analyse_source`, the same snapshot as the committed `docs/example-report.html`. Fused score is the 6 h median of the last 60 days; intervals are the real daily RUL checkpoints; the work order is the real drafted one (template narrative, no LLM). |
| `data/maintenance-agent.{json,js}` | `tools/export_maintenance_agent.py` | maintenance-agent: the orchestrator, rule-based planner, 16-rule verifier, signing gate and mock CMMS on synthetic alert `ALR-1004`, fixed clock. The clean run is approved and released; the unsafe run is the same draft after a signed edit removes isolation step 5.7. Timestamps are dropped and hashes shortened to 8 hex characters; the hash chain was checked intact before export. |

To regenerate (the two repositories sit next to this one in `github-repos/`):

```bash
python -m venv .venv && .venv/Scripts/pip install numpy pandas scipy scikit-learn pydantic cryptography
.venv/Scripts/python tools/export_asset_health.py ../asset-health ./scratch
.venv/Scripts/python tools/export_maintenance_agent.py ../maintenance-agent
.venv/Scripts/python tools/make_trace.py 1200 170      # the decorative hero trace (seeded, not measured data)
python tools/render_images.py                          # og.png and favicons (needs Playwright)
```

Every number in the prose (79 of 80, 4,603 probes, 99.5%, 59.6% and so on) appears in the corresponding repository README, in its Results section. The hero trace is a deterministic illustration and is labelled as one.

## Checks

```bash
python tools/qa.py shots     # screenshots (desktop, mobile, dark, light, reduced motion) into _preview/
python tools/qa.py demos     # clicks through both demos and prints what happened
python tools/qa.py checks    # console and CSP errors, file:// load, 360 px overflow, tab order, nav toggle
```

Lighthouse 13 on 15 Oct 2026 against a local static server that gzips like GitHub Pages (Python's `http.server` has no compression and a slow first byte on the dev laptop, which alone drops the score to the low 70s):

| Run | Performance | Accessibility | Best practices | SEO |
|---|---|---|---|---|
| Mobile (simulated slow 4G, 4x CPU) | 95 | 100 | 100 | 100 |
| Desktop | 98 | 100 | 100 | 100 |

Transfer size is about 45 KB gzipped (about 160 KB raw: HTML 37 KB, CSS 38 KB, JS 48 KB, data 36 KB); the page requests no images. Scores move by a point or two between runs. Re-run with:

```bash
npx lighthouse http://localhost:8000/ --only-categories=performance,accessibility,best-practices,seo --chrome-flags="--headless=new"
```

Other checks run: `html-validate` (clean), `lychee --offline` (no broken internal links), `typos` (clean), the QA script above (no console errors or CSP violations over HTTP or `file://`, no horizontal overflow at 360 px).

## Deploying

This is a GitHub Pages user site: push the contents of this folder to a repository named `darrshangovender.github.io` and enable Pages from the default branch. `.nojekyll` is included so the folder is served as is. Absolute URLs in the meta tags (canonical, Open Graph, sitemap) assume `https://darrshangovender.github.io/`.
