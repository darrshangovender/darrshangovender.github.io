Systems

Three systems for the maintenance loop, each built to be checked.

An alert is raised, the controlled procedure is found and quoted, a work order is drafted, and a person decides. Each repository runs offline with no API keys, states what its results were measured on, and lists its limitations.

asset-healthSynthetic data

Predictive maintenance, scored one failure at a time

Regime-aware anomaly detection, remaining useful life with an uncertainty interval, cost-aware alerting and structured work-order recommendations for mining and processing assets, run on a seeded synthetic fleet.

Key result

On 80 held-out synthetic failures: 79 warned 3+ days ahead vs 70 for the better of two tuned fixed-limit baselines, at about two-thirds of that baseline's illustrative cost. Still ahead when failure signatures are scaled to 30%; behind at 15%, and the README shows that curve.

What it cannot show

Anything about a real plant. The fleet is simulated, so the results describe the method, not a site.

plant-copilotSynthetic corpus

A bilingual procedures assistant that refuses when the documents are silent

Arabic and English assistant for SOPs and HSE procedures. Answers only from controlled documents, cites the exact clause and revision, applies access control before retrieval, and refuses when the answer is not there.

Key result

0 access-control leaks in 4,603 probes; every safety-critical clause quoted verbatim (64 of 64, against a simulated model that rewords everything); 15 of 22 (68.2%) on test questions whose target clauses no tuned question shares.

What it cannot show

Real documents: the corpus is 37 synthetic documents. The groundedness check catches 99.5% of the error types it was designed for and 15.7% of those it was not.

maintenance-agentSynthetic data

A supervised maintenance-planning agent with a safety case

Takes an alert, retrieves the relevant procedures with citations, drafts a work order, checks it with a rule-based safety verifier, and stops at a human approval gate. Every tool call is logged and replayable.

Key result

Blocked 99.5% of seeded unsafe drafts (1,195 of 1,201), with the six it misses listed; 0 of 55 correct drafts wrongly blocked; 15 of 15 approval-gate bypass attempts refused.

What it cannot show

That the rules are complete. A fully cited draft for the wrong failure mode still passes, which is why a person signs.

    Research harness

    Two pre-registered studies that publish their losses.

    closed-loop runs a maintenance stack as one loop on a simulated plant and attacks it on held-out seeds under a pre-registration. Version 0.2 asks the same question of NASA's C-MAPSS turbofan trajectories. Both publish a loss at the same size as a win. The first is entirely synthetic, and C-MAPSS is simulated by NASA's engine model, not field data.

    closed-loop v0.1Synthetic data

    A maintenance stack, run as one loop on a simulated plant

    • The shield behaved as its proof predicts: 0 violations of P1 to P3 in 500 episodes for each of two hostile proposers, against 306 of 500 and 150 of 150 with it off.
    • The thesis did not hold where it was registered: closing the loop did not move pooled coverage outside the band of 0.03 (C-PERC.pooled, a loss).
    • A second full run matched the first on 2,962 of the 2,967 records they share, in value, interval and sample size.

    Source, claims register and limits →

    closed-loop v0.2NASA C-MAPSS, simulated

    Does conformal remaining-life coverage survive a replacement policy?

    • V1, calibrated once, stayed inside the band when the loop closed: −0.0058 pooled over 373 evaluation units (interval −0.0255 to 0.0143), a loss for the thesis.
    • V2L, which learns from the lives the policy ends, lost coverage: −0.0767 pooled (interval −0.0864 to −0.0670), a win for the thesis.
    • One full run, on 10 November 2026, after the freeze.

    How I work

    Four habits that make the work checkable.

    1. 01

      Offline by default

      Tests, examples and benchmarks need no API keys and no network. Hosted-model paths are optional extras, so data can stay inside the client environment.

      no key, no network: pip install, then run
    2. 02

      Every number has a script

      Results are regenerated by a script in the repository and say what they were measured on: synthetic data, a simulated model, or a bundled corpus.

      e.g. python benchmarks/run.py rewrites the README tables
    3. 03

      Controls sit outside the model

      Rule-based verifiers, AST allowlists, access control before retrieval and human approval gates, not instructions in a prompt.

      the verifier above is a pure function of two JSON documents
    4. 04

      Limitations are written down

      Each README has a Limitations section that says what changes on real data.

      and a known-gaps list that stays in the denominator
