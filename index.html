01/Industrial AI

Three systems for the maintenance loop, each built to be checked.

An alert is raised, the controlled procedure is found and quoted, a work order is drafted, and a person decides. Each repository runs offline with no API keys, states what its results were measured on, and lists its limitations.

asset-healthraises the alert, with remaining useful life as an interval
→
plant-copilotsupplies the controlled procedure, cited by clause and revision
→
maintenance-agentdrafts the work order and waits for a person

The three are separate repositories that share no code. The hand-offs are adapter interfaces, not a tested integration, and the README of each says so.

asset-healthSynthetic data

Predictive maintenance, scored one failure at a time

Regime-aware anomaly detection, remaining useful life with an uncertainty interval, cost-aware alerting and structured work-order recommendations for mining and processing assets, run on a seeded synthetic fleet.

Key result
On 80 held-out synthetic failures: 79 warned 3+ days ahead vs 70 for fixed thresholds, at about two-thirds the cost. Still ahead when failure signatures are scaled to 30%; behind at 15%, and the README shows that curve.
Cannot show
Anything about a real plant. The fleet is simulated, so the results describe the method, not a site.

Source and results on GitHub →

plant-copilotSynthetic corpus

A bilingual procedures assistant that refuses when the documents are silent

Arabic and English assistant for SOPs and HSE procedures. Answers only from controlled documents, cites the exact clause and revision, applies access control before retrieval, and refuses when the answer is not there.

Key result
0 access-control leaks in 4,603 probes; every safety-critical clause quoted verbatim (64 of 64, against a simulated model that rewords everything); 68% correct on held-out questions it was never tuned on.
Cannot show
Real documents: the corpus is 37 synthetic documents. The groundedness check catches 99.5% of the error types it was designed for and 15.7% of those it was not.

Source and results on GitHub →

maintenance-agentSynthetic data

A supervised maintenance-planning agent with a safety case

Takes an asset-health alert, retrieves the relevant procedures with citations, drafts a work order, checks it with a rule-based safety verifier, and stops at a human approval gate. Every tool call is logged and replayable.

Key result
Blocked 99.5% of seeded unsafe drafts, with the six it misses listed; 0 of 55 correct drafts wrongly blocked; 15 of 15 approval-gate bypass attempts refused.
Cannot show
That the rules are complete. A fully cited draft for the wrong failure mode still passes, which is why a person signs.

    03/LLM infrastructure

    Cost, safety and reliability controls around the model.

    The parts a model should not be trusted to do for itself. Each repository runs offline and says what its number was measured on.

    guardrailexternal benchmark

    Safety gateway for model inputs and outputs: prompt-injection detection, PII redaction, groundedness checks and structured-output repair behind one policy layer. Saudi National ID/Iqama, IBAN and mobile detection with checksums.

    On public datasets it did not train on59.6%of labelled attacks caught (95% CI 52.5 to 66.3), with 0 false alarms on 178 benign prompts (upper bound 2.1%).
    Limitation, as written in the READMEThe detector is 46 regular expressions. Paraphrase, translation and encoded attacks pass, so it is one layer of defence, never the only control.

    cascade

    Verifier-gated model cascade: answer with the cheapest model first, escalate only when verification fails, fit the thresholds offline. Benchmarked on a simulated model.

    ResultCounts every verifier call at current prices. A 2-tier cascade is 5% cheaper at 99% of the strong model's accuracy; the 3-tier one costs more, and the README shows why.

    context-compress

    Prompt and RAG context compression with a fact-recall evaluator, so savings are reported next to what was lost.

    Result48% fewer tokens with every fact kept, where naive truncation saves 57% but keeps 21.7%. Synthetic RAG set.

    sql-guardrails

    Makes LLM-written SQL safe to execute: sqlglot AST allowlisting, read-only enforcement and optional EXPLAIN cost limits. Ships an adversarial corpus.

    ResultExecutes only the guard's own normalised SQL, so a parser disagreement between guard and database cannot become a bypass. 22 functions blocked permanently, beyond the reach of config.

    mcp-gateway

    MCP server wrapper with API-key auth, tenant isolation, per-tool guardrails, rate limits and an audit log. Serves the 2026-07-28 MCP revision and the 2025 revisions side by side.

    ResultSTRIDE threat model; 253 tests.

    agent-runtime

    Checkpointed state-machine executor for agents: resume after a crash, identical-call loop breaker, model fallback chain, schema self-correction.

    StatusDesign reference; no headline number.

    thinking-loop

    Published test-time reasoning strategies behind one interface, adjudicated by a critic, under hard token, time and cost budgets.

    StatusBenchmark harness; a real-model run needs your own key.

    rag-eval-harness

    Faithfulness, answer relevance and recall@k for RAG pipelines, wired into CI so a regression fails the build.

    StatusA CI gate, not a benchmark.

    More on GitHub: domain work such as lease abstraction and affordability scoring for LeasEase, the rental-trust startup I founded, a WhatsApp agent kit with POPIA-aware redaction, and smaller RAG, routing and evaluation libraries.

    04/How I work

    Four habits that make the work checkable.

    1. Offline by default

      Tests, examples and benchmarks need no API keys and no network. Hosted-model paths are optional extras, so data can stay inside the client environment.

      no key, no network: pip install, then run

    2. Every number has a script

      Results are regenerated by a script in the repository and say what they were measured on: synthetic data, a simulated model, or a bundled corpus.

      e.g. python benchmarks/run.py rewrites the README tables

    3. Controls sit outside the model

      Rule-based verifiers, AST allowlists, access control before retrieval and human approval gates, not instructions in a prompt.

      the verifier above is a pure function of two JSON documents

    4. Limitations are written down

      Each README has a Limitations section that says what changes on real data.

      and a known-gaps list that stays in the denominator
